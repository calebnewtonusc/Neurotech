# Hardware Decision Memo - Project 1 Input Path

**Date locked:** June 5, 2026
**Author:** Mark Lin
**Status:** Locked Week 1 decision
**Applies to:** Project 1, Neuroadaptive Assistive Workstation

## Locked Decision

Project 1 will build the closed-loop workstation on a simulated low-bandwidth input harness first, then swap in open surface EMG after raw signal access, timestamping and repeatability are verified.

**Primary Week 1-2 input:** simulated low-bandwidth input with explicit simulation labels, deterministic seeds, noise parameters and event logs.
**Primary real-hardware target:** open surface EMG, starting with MyoWare 2.0 for the fastest inspectable path and moving to OpenBCI if multi-channel signal quality is worth the setup cost.
**Fallback:** continue with simulated low-bandwidth input if real EMG cannot be logged, repeated and measured above baseline by June 19, 2026.
**Not locked:** Meta Neural Band, unless programmatic developer access to usable raw or event-level signals is actually available. MindRove is treated as an older project-card reference, not the locked dependency, unless the device and SDK are verified before the hardware kill-switch.

This decision favors a measured system over a fragile hardware bet. The workstation, logger, decoder interfaces, metrics and baseline comparisons can ship even if EMG hardware slips.

## Rationale

The summer cannot depend on an uncertain wearable API. The hard part of Project 1 is not owning a sensor; it is proving a closed-loop assistive system can be logged, evaluated and described honestly. A simulated low-bandwidth harness lets the team build the same command vocabulary, latency instrumentation, correction flow and prediction-assisted interface that real EMG will later drive.

Open surface EMG remains valuable because it introduces real biological noise, electrode placement sensitivity, fatigue and day-to-day variability. Those are exactly the constraints that make the project credible. But EMG only strengthens the application if the team states what it measures: muscle activation, not cortical activity.

## June 19 Kill-Switch Criteria

Real EMG can replace the simulator only if all of these are true by June 19, 2026:

- Raw samples or stable event features can be exported programmatically with timestamps.
- A 10-minute session has less than 5% sample dropout after documented preprocessing.
- At least four intentional input classes can be repeated across three short blocks.
- A simple baseline classifier beats chance on held-out windows without leakage.
- End-to-end command latency can be measured with p50 and p95 values.
- The write-up states electrode placement, preprocessing, session length and fatigue limits.

If any criterion fails, Project 1 remains simulated-first. Real EMG can still be added later as an exploratory extension, but it cannot block the core workstation and metric package.

## Correct vs. Incorrect Framing

| Situation | Correct | Incorrect |
|---|---|---|
| Simulated harness result | "The simulated low-bandwidth input harness completed the task with 220 ms median loop latency." | "The EMG system achieved 220 ms latency" when no EMG was used |
| Surface EMG result | "The surface EMG classifier separated four forearm muscle-activation patterns." | "The BCI decoded four intentions from brain activity" |
| Assistive workstation demo | "A BCI-inspired closed-loop assistive-control demo using muscle input or simulated input." | "A Neuralink-like implanted BCI demo" |
| Prediction gain | "Prediction assistance reduced corrections versus gesture-only control in this protocol." | "The system understands user intent" |

## Locked Metrics

| Metric | Primary comparison | Honest limit |
|---|---|---|
| Command accuracy | Simulated truth labels or held-out EMG gesture labels vs chance | Does not measure general intent |
| End-to-end latency | p50/p95 from input event to UI action | Depends on local machine and input route |
| Completion time | Prediction-assisted vs gesture-only baseline | Single workflow may not generalize |
| Correction rate | Corrections per task trial vs gesture-only baseline | Lower corrections do not prove lower fatigue by themselves |
| User burden | Post-session fatigue/effort rating vs baseline | Subjective, small-n unless repeated across users |
| Calibration time | Minutes and samples required before usable control | Hardware-specific and electrode-placement-sensitive |

## Locked Decision Rationale

This decision is stronger than a hardware-first decision because it separates the scientific claim from the device procurement risk. The team can prove logging discipline, closed-loop evaluation and honest reporting immediately. Real EMG improves ecological validity only after it clears the kill-switch.
